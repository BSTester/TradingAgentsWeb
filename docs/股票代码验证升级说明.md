# 股票代码验证升级说明

## 升级概述

已完成对全球三大市场（美股、港股、A股）股票代码的严格验证规则升级，基于各交易所的官方编码规范，确保只接受符合标准的股票代码。

## 编码规则研究

通过详细研究各市场的编码规则，我们了解到：

### 美股编码特点
- **NYSE**：通常1-3个字母（如 F, IBM, JPM）
- **NASDAQ**：通常4-5个字母（如 AAPL, MSFT, GOOGL）
- **格式**：纯字母，1-5个字符

### 港股编码特点
- **格式**：5位数字（2008年后统一，兼容4位旧格式）
- **主板**：代码范围 00001-03999
- **创业板**：以8开头
- **后缀**：可选 .HK

### A股编码特点
- **格式**：6位数字
- **沪市**：600/601/603/605（主板）、688（科创板）
- **深市**：000/001（主板）、002（中小板）、300/301（创业板）
- **后缀**：沪市可选.SH，深市可选.SZ

## 主要改进

### 1. 严格的A股代码验证

#### 沪市（上海证券交易所）
- ✅ **主板**: 600、601、603、605 开头
- ✅ **科创板**: 688 开头
- ✅ **后缀**: 可选 .SH
- ❌ 拒绝其他不符合规则的6位数字代码

#### 深市（深圳证券交易所）
- ✅ **主板**: 000、001 开头
- ✅ **中小板**: 002 开头（已并入主板）
- ✅ **创业板**: 300、301 开头
- ✅ **后缀**: 可选 .SZ
- ❌ 拒绝其他不符合规则的6位数字代码

### 2. 后缀匹配验证

- ✅ 沪市代码只能使用 .SH 后缀
- ✅ 深市代码只能使用 .SZ 后缀
- ❌ 拒绝后缀与代码不匹配的情况（如 000001.SH）

### 3. 详细的错误提示

前端和后端都提供了详细的错误信息：

**示例错误提示：**
```
无效的A股代码：123456

沪市代码必须以 600/601/603/605/688 开头
深市代码必须以 000/001/002/300/301 开头
```

**完整格式说明：**
```
无效的股票代码格式：XXX

支持格式：
• 美股：1-5个字母（如 AAPL、TSLA）
• 港股：4-5位数字或带.HK后缀（如 0700、00700.HK）
• A股沪市：600/601/603/605/688开头（如 600519、688001.SH）
• A股深市：000/001/002/300/301开头（如 000001、300750.SZ）
```

## 港股代码标准化

### 自动添加后缀

后端接口对港股代码进行特殊处理，确保统一格式：

| 用户输入 | 后端处理后 | 说明 |
|---------|-----------|------|
| `0700` | `0700.HK` | 自动添加后缀 |
| `00700` | `00700.HK` | 自动添加后缀 |
| `0700.HK` | `0700.HK` | 保持不变 |
| `00700.HK` | `00700.HK` | 保持不变 |

### 优势

1. **数据一致性**：数据库中港股代码格式统一
2. **用户友好**：用户可以输入带或不带后缀，系统自动处理
3. **系统兼容**：与数据源API保持一致（大多数API要求港股带.HK）

### 实现函数

```python
def normalize_ticker_with_suffix(ticker: str) -> str:
    """港股自动添加.HK后缀，其他市场保持不变"""
    normalized = normalize_ticker(ticker)
    
    # 如果已经带了.HK后缀，直接返回
    if normalized.endswith('.HK'):
        return normalized
    
    # 检查是否是港股（4-5位纯数字）
    if normalized.isdigit() and 4 <= len(normalized) <= 5:
        return f"{normalized}.HK"
    
    return normalized
```

## 技术实现

### 前端验证流程
1. 用户输入股票代码
2. `handleInputChange` 触发实时验证
3. 调用 `validateTickerFormat()` 检查格式
4. 如果无效，调用 `getTickerErrorMessage()` 获取详细错误
5. 在UI中显示错误提示

### 后端验证流程
1. 接收分析请求
2. 调用 `normalize_ticker()` 标准化代码
3. 调用 `validate_ticker()` 验证格式
4. 如果无效，返回 HTTP 400 错误和详细信息
5. 如果有效，调用 `normalize_ticker_with_suffix()` 添加市场后缀（港股自动添加.HK）
6. 调用 `detect_market()` 识别市场类型
7. 使用标准化后的代码存储和处理
